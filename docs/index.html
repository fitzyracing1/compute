A clock built to run out of room
on purpose.

Unix time counts seconds continuously since 1970, in a counter that runs out of room on 2038-01-19. This one resets every week, by design, so it never gets there.

Mon 09:00
17:00
Tue – Thu matrix up, services quiet
Fri 09:00
Sat – Sun down · 17:00 → 09:00
  • services active
  • matrix up, services quiet
  • fully down

the problem

A 32-bit signed Unix timestamp is a single number that has been counting up since 1970 and never stops. It has a ceiling, and that ceiling arrives on 2038-01-19. Anything still reading time that way has to either widen the integer or stop counting continuously.

how it works

Time is split into two numbers instead of one running counter.

cycle_id
Increments once per week, at Monday 09:00. Ticking once a week instead of once a second means a 32-bit cycle_id doesn't run out of room for roughly 41 million years.
offset
Seconds since the current cycle's matrix window opened. Resets to zero every Monday 09:00, so it never accumulates toward an overflow point — the matrix window is at most 374,400 seconds, comfortably under 2¹⁹.

Each week nests two windows: the matrix window (Monday 09:00 to Friday 17:00, the compute layer is up), and the services window inside it (Monday 09:00–17:00 and Friday 09:00–17:00, when the application layer takes work). Outside the matrix window — Friday 17:00 to the following Monday 09:00 — everything is down. That gap is the reset between cycles.

Anything that needs a real calendar date still can — one translation function handles it, using arbitrary-precision integers so it's never the thing that overflows: 

absolute_time = epoch_anchor + cycle_id * WEEK + offset_seconds

who it's for

  • Batch or scheduled compute that only needs to know how far into the current work window it is, not the absolute date.
  • Edge or embedded devices that don't need wall-clock accuracy — just a bounded, self-resetting operational cycle.
  • Systems where downtime is already scheduled, so the weekend reset gap costs nothing extra.

get started

pip install compute
from datetime import datetime, timezone
from compute import CycleClock

clock = CycleClock()
now = datetime.now(timezone.utc)

clock.matrix_active(now)      # is the compute layer up?
clock.services_active(now)    # is the application layer taking work?
clock.next_boundary(now)      # when does that next flip?
